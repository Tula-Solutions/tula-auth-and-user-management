# Codebase map

An interactive graph of this repository: its files, functions and classes and how they relate
(what imports, calls, contains and configures what), grouped into 20 layers, with a 15-step
guided tour for a first read. It is beside this page, in
`docs/codebase-map/.ua/knowledge-graph.json`.

It was generated by [Understand-Anything](https://github.com/Egonex-AI/Understand-Anything)
(MIT, a Claude Code plugin, version 2.9.7). **It is a snapshot of commit `7f173cd0` and is not
kept up to date.** Nothing in the build, the tests or the product reads it. Read
["Limits"](#limits) before relying on it.

## Opening it

The graph is a JSON file; the plugin's dashboard draws it. The dashboard is served from your
own disk on `127.0.0.1` only, and nothing is uploaded. The tool reads a folder named `.ua`
inside the directory it is pointed at, which is why the graph is in `docs/codebase-map/.ua/`.

### By hand

From the `packages/dashboard` directory of a checkout of the plugin, with its dependencies
installed:

```bash
GRAPH_DIR=<path to this repository>/docs/codebase-map npx vite --host 127.0.0.1
```

It prints a `Dashboard URL` that ends in `?token=…`. Open that address as printed: the token is
required, and the dashboard answers nothing without it.

### With the plugin in Claude Code

```bash
claude plugin marketplace add Egonex-AI/Understand-Anything
claude plugin install understand-anything@understand-anything --scope user
```

The plugin's skills look for `.ua/` at the root of the repository, so copy the graph there
first (the root copy is git-ignored):

```bash
cp -R docs/codebase-map/.ua .ua
```

Then start a new Claude Code session in this repository and run `/understand-dashboard`. It
starts the same dashboard and gives its address.

| Skill | |
| --- | --- |
| `/understand-dashboard` | Opens the graph. |
| `/understand-chat` | Answers a question from the graph. |
| `/understand` | Generates the graph, or updates it from the files that changed since the last run. |

## Refreshing it

Run `/understand` at the root of the repository, which writes `.ua/` there, then copy the four
shared files back and commit them:

```bash
cp .ua/knowledge-graph.json .ua/meta.json .ua/config.json .ua/.understandignore docs/codebase-map/.ua/
```

Update the commit and the numbers on this page in the same change.

## What it covers and what it leaves out

989 files were analysed: the sources of the API, the packages, the dashboard, the native SDKs
and the examples, the configuration, and the guides under `docs/`.
[`.understandignore`](.ua/.understandignore) lists what was left out, with the reason:

- **Tests**: `*.test.*`, `*.spec.*`, `*.integration.ts`, `*.suite.ts`, snapshots, `testing/`
  directories, the Swift, Kotlin and Android test sources and `e2e/tests/`. The graph is of
  the product, and there are more test files than source files.
- **Generated files**, each a copy of something the graph already holds: `*.gen.ts`,
  `*.gen.css`, `packages/contract/openapi.json`, the conformance JSON Schemas,
  `docs/reference/`, the generated Swift and Kotlin types, `packages/create-tula/templates/`,
  `packages/db/migrations/`, the vendored native sources of `@tula-tech/expo-screens` and the
  dashboard's shadcn primitives (`apps/dashboard/src/components/ui/`).
- **Data and binaries**: `conformance/scenarios/`, images, PDFs, Xcode project files, the
  Gradle wrapper, `.changeset/`.
- **Local state and build output**: `.env` files, `.release/`, `.build/`, `.gradle/`,
  worktrees and the like.
- **Prose about the work rather than the product**: `.claude/` (the agent rules), `docs/adr/`
  and `docs/plans/`.

To include one of these, remove its line from `.understandignore` and run `/understand` again.

## Limits

- **The summaries were written by a language model** (Claude Sonnet), one batch of files at a
  time. Some function summaries come from the function's name or the first line of its JSDoc
  block rather than from its full source. A summary can be wrong or miss the point. The
  source, [`AGENTS.md`](../../AGENTS.md) and the [decision records](../adr/) are the
  authority; the map is a way in.
- **A Swift import edge is to a module, not to a file.** The tool's extractor does not resolve
  Swift imports, and Swift imports a module, never a file. The 228 import edges that start at
  a Swift file link each of 16 files to every file of the module it imports (`TulaAuth`,
  `TulaAuthUI`); between two files of one module, which need no import, there is no edge at
  all. Which Swift file uses which is not in the graph.
- **It is a snapshot** of commit `7f173cd0`, and it goes stale with every change after it.
  `autoUpdate` is off and no hook, script or CI job regenerates it: it is as old as the commit
  in `.ua/meta.json` until someone runs `/understand` and commits the result.
- **Nothing depends on it.** The build, the tests and the product never read it; it is under
  `docs/`, which Biome and the Docker build context already skip.
- **The dashboard was not written or reviewed here.** It is the plugin's code, run on your
  machine.
